    Rotations, frames and gimbal lock, explained

    A rotation matrix is three arrows

    A coordinate frame is an origin and three perpendicular unit arrows, x, y and z. A 3×3 rotation matrix R stores the turned frame's arrows as its columns, written in the fixed frame: the first column is where x ends up, the second where y ends up, the third where z ends up. That is why the matrix on the 3D view has its columns coloured like the axes. Multiplying a vector by R turns it: Rz(90°) sends x = (1, 0, 0) to (0, 1, 0).

    Because the columns are perpendicular unit arrows, RTR = I: turning keeps every length and angle. And det R = +1: a right-handed frame stays right-handed. A matrix that passes the first test but has a determinant of −1 is a mirror image, not a turn. The page checks both for every matrix it shows, and for any matrix you type in.

    Why order matters

    Turn a book 90° about one edge, then 90° about another, and it ends up in a different position from doing the same two turns the other way round. In matrices, R1R2 ≠ R2R1 in general: rotations in 3D do not commute. Small turns almost do, which is why the effect surprises people. It only becomes obvious with big angles, so the examples use 90°.

    Moving axes or fixed axes?

    “Rotate about x, then about y” is ambiguous until you say which y. Turning about the moving axes (intrinsic) means each turn is about the object's own, already-turned axes, like an aircraft's yaw, pitch and roll. The matrices then multiply on the right: R = R1R2…Rn. Turning about the fixed axes (extrinsic) means each turn is about the world's axes, which never move. The matrices multiply on the left: R = Rn…R2R1.

    The two are linked: turning about the moving axes in one order gives exactly the same result as turning about the fixed axes in the reverse order. So the “Compare reversed order” ghost is also where the object would end up under the other convention. Switch the toggle and the solid object jumps to where the ghost was.

    Homogeneous transforms in robotics

    A robot needs position as well as orientation. A 4×4 homogeneous transform T = [R p; 0 1] holds both: R turns and p moves. Chaining joints and links is then just matrix multiplication, read along the arm: in the two-link arm example, T = Rz(base) Ry(shoulder) T(upper arm) Ry(elbow) T(forearm), each step in the frame left by the one before. The inverse needs no general matrix inversion: T−1 = [RT −RTp; 0 1].

    Order matters here too. Translate then rotate (about the moving axes) moves the object first and then spins it on the spot. Rotate then translate turns it first and then sends it along its new x axis, so it ends up somewhere else.

    Gimbal lock

    Three angles are enough to describe any orientation. The usual aerospace set is yaw ψ about z, then pitch θ about the new y, then roll φ about the newest x. A gimbal is the physical version: three nested rings, each turning about one of those axes. When the pitch reaches ±90°, the roll axis swings round until it lines up with the yaw axis. Yaw and roll then turn the object about the same line, so the three angles only give two independent directions to turn in. A degree of freedom has gone: no small change of ψ, θ or φ can turn the object about the missing direction.

    The orientation itself is perfectly ordinary. It is the description that breaks: at θ = 90° only ψ − φ is defined, so the angles cannot be read back uniquely from the matrix.

    A unit quaternion q = (w, x, y, z) = (cos α/2, n sin α/2) describes the same orientation as one turn α about an axis n. It uses four numbers tied together by w2 + x2 + y2 + z2 = 1, and the extra number removes the singularity: the quaternion changes smoothly through θ = 90°, and slerp (spherical linear interpolation) moves between two orientations along the shortest path at a steady rate. In the interpolation demo, straight-line Euler interpolation from – to – swings the object through – in total, while slerp turns it just –.

    Worked example

    Start with the frame lined up with the world. Turn 90° about x: y goes to where z was, and z to −y. Now turn 90° about the new y axis, which points along the world z axis: that carries x round to the world y axis. So Rx(90°)Ry(90°) sends x to y.

    The other way round, Ry(90°) first tips x down to −z. The second turn is about that new x axis, so it cannot move it: x stays pointing down. Ry(90°)Rx(90°) sends x to −z. The two results are a single turn of – apart. Load the two “order matters” examples and press Play to watch both happen.

    Conventions used here

    Right-handed frames with z up; rotations that turn vectors (v′ = R v, column vectors), with Rx, Ry, Rz as in Lynch and Park's Modern Robotics; quaternions written (w, x, y, z) with the scalar first and multiplied with Hamilton's rule. Diebel's report uses the opposite, passive convention (the matrix that converts world coordinates into body coordinates), so his matrices are the transposes of the ones here. The formulas on this page were checked against both. With z up, a positive pitch tips the nose down.

    What is approximate

    Nothing in the maths: the matrices are exact apart from floating-point rounding, which shows up in the checks as errors of about 10−16 or less. The 3D picture is a perspective drawing, not to scale, and the object is just a shape that makes orientation easy to see. A typed matrix counts as a rotation when its columns have unit length and are perpendicular to within 0.001 (so values typed to three decimals pass) and its determinant is positive.
